# Формат APC-маркера shell-интеграции не объединяется в общую схему кодирования/разбора

Решение (кандидат №6 из архитектурного ревью `/improve-codebase-architecture`, 2026-07-17, отклонён при `/codebase-design` grilling 2026-07-18): раскладка полей маркера (`nonce·user·host·euid·exit·sudoUser·pwd·nonce`, разделитель `\x1f`) остаётся продублированной в трёх местах — строке настройки `shellIntegrationSetup(nonce)` (`src/main/ssh/shellIntegration.ts`), разборе `parseMarker` там же, и тестовом хелпере `mk()` (`shellIntegration.test.ts`) — без единой декларации, из которой генерировались бы все три.

**Почему это не просто отложенная уборка, а сознательный отказ.** Исходное ревью помечало кандидата как Speculative — «выгода проявится только при следующем изменении протокола». К моменту grilling это изменение уже произошло: маркер расширили с 5 до 6 полей (добавили `SUDO_USER` для различения `sudo`-рута от настоящего root-логина). Риск, ради которого предлагалось объединение (забыли обновить одно из трёх мест при изменении формата), не подтвердился — все три места обновлены согласованно, включая явно написанный и покрытый тестом путь обратной совместимости со старым 5-полевым форматом (`shellIntegration.test.ts`, тест «маркер старого формата»).

**Седьмое поле (2026-10-16).** Первым полем стал nonce сессии (подделка маркера выводом сервера, тикет 14 `security-scan-2026-10`); все три места (`mk()` к этому времени скопирован ещё в `shellIntegrationSession.test.ts` и `shellChannel.test.ts`) обновлены вместе, рассинхрона не возникло — решение остаётся в силе. Путь обратной совместимости со старым 5-полевым форматом при этом удалён: каждый маркер печатает настройка той же сессии, а маркер старого формата nonce не несёт.

**Перестановка полей (2026-10-20).** Путь (`$PWD` — имя каталога задаёт сервер) переехал в конец, за ним nonce повторяется ещё раз (тикет 17 `security-scan-2026-10`): `\x1f` в имени каталога больше не сдвигает euid/exit, а `ESC \` в нём не обрывает маркер — `BreadcrumbParser` ищет конец маркера с nonce сессии по `\x1f nonce ESC \`. Это четвёртое место, знающее раскладку (поиск конца маркера в потоке). Все места — настройка, `parseMarker`, поиск конца, три копии `mk()` — обновлены одним изменением, рассинхрона не возникло; решение остаётся в силе.

**Смена завершителя (2026-10-20).** Маркер сессии кончается на BEL (`\x1f nonce BEL`), а не на `ESC \`: BusyBox ash с `FEATURE_EDITING_FANCY_PROMPT` (Alpine) разбирает `\`-последовательности в уже развёрнутом PS1, и `\` из `ESC \` склеивался с первым символом приглашения пользователя (`\$` → `#`) — после первого маркера ни один не принимался, хвост с nonce уходил на экран. Найдено живой проверкой тикета 17, баг старше него. Маркеры без nonce сессии ищутся до первого `ESC \` или BEL. Поменялись настройка, поиск конца и три копии `mk()` — одним изменением, рассинхрона не возникло; решение остаётся в силе.

**Дополнительная причина.** То, что в отчёте называлось «encoder», не является рантайм-логикой в нашем процессе — `shellIntegrationSetup` printf-строка (параметризованная только nonce), которую значениями подставляет удалённый shell, а не наш TypeScript. Объединить можно было бы только список полей (имена/порядок), не пару функций кодирования/декодирования в привычном смысле — и даже это принесло бы пользу только для основного (текущего) формата: ветку обратной совместимости со старым форматом всё равно пришлось бы писать отдельно вручную, не выводя из общей схемы.

**Когда пересматривать.** Если при будущем изменении формата маркера (восьмое поле, смена разделителя и т.п.) обнаружится реальный баг рассинхрона между тремя местами — стоит вернуться к этому решению с новой, на этот раз подтверждённой на практике причиной.

Решение принято 2026-07-18.
